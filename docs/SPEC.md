# 서비스 명세

이 문서는 공간의 지은이가 **무엇을 하는지** 적습니다. 지키는 규칙, 데이터, 화면별 동작, 운영 규칙이 여기에 있습니다. 서비스를 처음 이해할 때, 그리고 기능을 바꾸기 전에 읽습니다. 기술 선택의 이유는 [DECISIONS.md](DECISIONS.md), API 모양은 [API.md](API.md), 화면 수치는 [DESIGN.md](DESIGN.md)에 있습니다.

## 1. 지키는 규칙

이 절의 규칙이 다른 문서와 다르면 이 절이 기준입니다. 대부분은 백엔드 통합 테스트로 확인합니다.

**서비스 성격**

- 좋아요, 별점, 랭킹, 인기순을 만들지 않습니다. 저장 수, 팔로워 수, 조회수도 화면과 공개 API 응답에 넣지 않습니다. 관리자 화면의 작업용 숫자(만든 사람의 공간 수, 검토 대기 건수)만 예외입니다.
- 감상(`impression`), 감각(`sense_*`), 한 줄(`daily_picks.line`), 에세이는 사람이 씁니다.

**URL과 상태**

- 공간과 만든 사람의 `slug`는 처음 공개한 뒤 바꾸지 않습니다. 공개 URL은 한 번 정하면 바꾸지 않습니다.
- 공간은 지우지 않습니다. 폐업한 공간은 `closed`로 둡니다.
- 상태는 4절의 전환표대로만 바꿉니다. 공개한 공간을 작성 중으로 되돌리지 않습니다.
- "필수" 항목은 공개할 때 검사합니다. DB의 NOT NULL은 최소로 두고, 검사 규칙은 백엔드 `PublishRules`와 프론트 Zod 스키마에 1:1로 둡니다.

**피드**

- 공간은 월~금 오전 8시(KST)에 공개됩니다. 공개 여부는 조회할 때 `pick_date 08:00 KST <= 지금`으로 계산합니다.
- 시간 계산은 서버만 합니다. 프론트는 서버가 준 값을 그립니다. 시각은 UTC(`timestamptz`)로 저장하고, KST는 경계를 계산할 때만 씁니다.
- 피드 카드의 팔로우 버튼은 아직 팔로우하지 않은 사람에게만 보입니다. 프로필과 상세에서는 팔로우·팔로잉이 둘 다 보입니다.

**로그인과 권한**

- 피드, 둘러보기, 공간 상세, 만든 사람 프로필은 로그인 없이 봅니다. 저장·팔로우·제보를 누를 때만 로그인 시트를 띄우고, 로그인한 뒤 누른 동작을 이어서 끝냅니다.
- 관리자 API(`/api/admin/**`)는 `role=admin`만 부릅니다. 관리자는 환경 변수 `ADMIN_EMAILS`로만 정합니다.
- 개발용 로그인(`POST /api/dev/login`)은 `dev`·`test` 프로필에만 있습니다. 고정 시계(`FIXED_NOW`)와 개발용 시드는 `dev` 프로필에만 있습니다. 운영 프로필에는 이 빈들이 생기지 않습니다.

**화면 너비**

- 기준 너비는 375px입니다. 공개 화면은 데스크톱에서 최대 480px로 가운데 둡니다. 관리자 화면만 최대 960px입니다.

## 2. 무엇을, 왜

### 목표

1. 공간에서 감동받는 사람을 모읍니다.
2. 만들면서 풀스택을 배우고, 그 과정을 보여 줍니다. 로그인, 권한, CRUD, 파일 업로드, 예약 공개, 배포가 들어갑니다.

서비스의 조용한 결을 해치지 않는 한, 2번에 필요한 기능은 넣습니다.

### 결정 원칙

1. "이 공간은 다녀온 뒤에도 오래 생각나는가?"에 도움이 되는 쪽을 고릅니다.
2. 바꾸기 비싼 것(데이터 구조, URL, 로그인 방식)만 먼저 확정합니다. 문구와 색은 바꿀 수 있는 값으로 둡니다.
3. 혼자 운영할 수 있는 쪽을 고릅니다.
4. 설명할 수 있는 코드만 넣습니다.

### 핵심 결정

| 질문 | 결정 | 바꾸기 비용 |
| --- | --- | --- |
| 무엇을 저장·팔로우할 수 있나 | 등록된 공간과 만든 사람만. 없으면 제보 | 높음 |
| 운영자 표시와 사용자 상태가 겹치는 문제 | 운영자는 "머물러 봄" 배지, 사용자는 "가고 싶어요 / 다녀왔어요" | 중간 |
| 로그인은 언제, 무엇으로 | 저장·팔로우·제보 때만. 구글, 서버 세션 | 높음 |
| 홈에 무엇을 두나 | 하루 한 곳 피드. 월~금 오전 8시(KST)에 한 곳씩 공개 | 중간 |
| 공간 콘텐츠를 어디에 두나 | PostgreSQL + 관리자 등록 폼 | 높음 |
| 사진을 어디에 두나 | Cloudflare R2. 브라우저에서 변환한 뒤 서명된 URL로 직접 업로드 | 중간 |
| 영상·인스타 게시물은 | 공식 임베드. 누를 때 불러옴 | 낮음 |
| 지도는 | 네이버지도·카카오맵 검색 링크만 | 낮음 |
| 제보는 어떻게 받나 | 공간 제보는 `places`에 `suggested` 상태로. 관리자 화면에서 검토 | 중간 |
| 화면 구조는 | 인스타그램식. 만든 사람 = 프로필 + 3열 사진 격자, 하단 탭 바 | 중간 |
| 좋아요와 숫자는 | 없음. 저장이 북마크 역할 | 낮음 |

### 하루 한 곳 피드

- 월요일부터 금요일까지 매일 오전 8시(KST)에 공간 한 곳이 열립니다. 한 주에 다섯 곳입니다.
- 피드에는 이번 주에 지금까지 열린 공간만 나옵니다. 수요일 오후라면 월·화·수 세 곳입니다.
- 주말에는 새 공간이 없고 그 주 다섯 곳이 그대로 보입니다. 금요일 저녁에 그 주 다섯 곳을 뉴스레터로 묶어 보낼 계획입니다.
- 편성된 공간이 없는 날은 비워 둡니다. 시스템이 다른 공간으로 채우지 않습니다.
- 이유: 하루 한 곳이라 조용한 결과 맞고, 매일 다시 올 이유가 생깁니다. 매일 오지 않는 사람은 쌓인 공간을 몰아 봅니다.

### 인스타그램에서 가져오는 것과 버리는 것

| 인스타그램 요소 | 결정 |
| --- | --- |
| 프로필 + 3열 사진 격자 | 가져옴 → 만든 사람 프로필 |
| 사진 옆으로 넘기기 | 가져옴 → 공간 상세 |
| 저장(북마크) | 가져옴 → 가고 싶어요 / 다녀왔어요 |
| 하단 탭 바 | 가져옴 → 오늘 · 둘러보기 · 내 공간 |
| 끝없는 피드 | 버림 → 끝이 있는 하루 한 곳 피드 |
| 좋아요, 숫자 | 버림 |
| 댓글, DM, 스토리 | 버림 |

| 용어 | 화면 문구 | 코드 이름 | 뜻 |
| --- | --- | --- | --- |

| 오늘의 공간 | ○요일의 공간 | `dailyPick` | 특정 날짜에 피드로 공개되는 공간 + 에디터의 한 줄 |

| 머물러 봄 | 머물러 봄 | `visitedByEditorOn` | 에디터가 직접 다녀온 공간의 배지 |
| 만남의 출처 | ○○으로 만남 | `source` | 직접 가지 않은 공간을 알게 된 기사·영상 |
| 저장 | 가고 싶어요 / 다녀왔어요 | `save.status`: `want` / `been` | 사용자의 개인 표시 |
| 팔로우 | 팔로우 / 팔로잉 | `follow` | 만든 사람 구독. 알림 없이, 내 공간의 팔로잉 탭에서 그 사람들의 공간을 모아 봅니다. 새로 공개된 공간은 "새로운" 표시와 탭의 점으로 알립니다 |

| 관리자 | — | `role: admin` | 콘텐츠를 등록하고 제보를 검토하는 사람(에디터) |

쓰지 않는 말: 맛집, 핫플, 성지, 평점, 랭킹, 리뷰, 좋아요.

## 4. 데이터

모든 데이터는 PostgreSQL 하나에 둡니다. 스키마는 Flyway 마이그레이션으로만 바꿉니다. 컬럼 타입과 제약의 기준은 [마이그레이션 파일](../backend/src/main/resources/db/migration/)입니다. 이 절은 각 테이블의 역할과 규칙만 적습니다.

### "필수"는 공개할 때 검사한다

제보된 공간은 이름과 지역뿐이고, 작성 중인 공간도 빈칸이 많습니다. 그래서 DB의 NOT NULL은 최소로 두고, `published`로 바꿀 때 서버가 필수 항목을 검사합니다. 관리자 폼도 같은 규칙으로 검사합니다. 검사 키와 문구는 [API.md "공개 시 검증"](API.md#공개-시-검증--publishrules)에 있습니다.

### `places`

| 컬럼 | 공개 시 필수 | 규칙 |
| --- | --- | --- |
| `slug` | ✓ | 영문 소문자·숫자·하이픈. 처음 공개한 뒤 바꿀 수 없음 |
| `name` | ✓ (제보 때부터) | |
| `kind` | ✓ | cafe, bar, restaurant, stay, garden, museum, gallery, bookstore, shop, religious, public, other |
| `region` | ✓ (제보 때부터) | "시·도 시·군·구" (예: "경기 양평군") |
| `address` | ✓ | |
| `lat`, `lng` | | 관리자 폼에서 받지 않습니다. 시드나 DB에 값이 있으면 검색용 구조화 데이터에만 씁니다 |
| `access` | ✓ | walk_in, reservation, ticket, guests_only |
| `visit_note` | | 방문 전에 알아야 할 것 한 줄(100자) |
| `summary` | ✓ | 목록·공유 카드의 한 문장(60자) |
| `impression` | ✓ | 에디터의 감상(400자) |
| `sense_light` `sense_sound` `sense_scent` `sense_touch` | | 각 60자. 모르면 비움 |
| `essay` | | 마크다운. 없으면 영역을 숨김 |
| `visited_by_editor_on` | | 있으면 "머물러 봄". 년·월만 표시 |
| `status` | — | suggested, draft, published, paused, closed, rejected |
| `suggested_by`, `suggestion_reason`, `suggestion_link`, `suggestion_maker_hint` | | 제보한 사람과 제보 때 쓴 내용 |
| `published_at` | — | 처음 공개한 시각. 둘러보기 정렬 기준 |

**공개 시 추가 검사**: 출처가 있는 크레딧 1개 이상 · 사진 1장 이상 또는 임베드 1개 이상 · "머물러 봄"이 없으면 출처 1개 이상 · 모든 사진에 `alt`와 `credit`, `license`가 `own`이 아닌 사진에는 `source_url`.

**상태 전환**

| 지금 | 바꿀 수 있는 상태 |
| --- | --- |
| suggested | draft, rejected |
| draft | published |
| published | paused, closed |
| paused | published, closed |
| closed, rejected | 없음 |

공개한 공간을 draft로 되돌리지 않습니다. 저장한 사용자가 있기 때문입니다. 내리려면 closed로 바꿉니다.

### 공간에 딸린 테이블

| 테이블 | 주요 컬럼 | 규칙 |
| --- | --- | --- |
| `place_credits` | place_id, maker_id, role, verified, source_url, position | role: planning, branding, architecture, interior, landscape, lighting, furniture, scent, photography, owner, other. verified면 source_url 필수(DB CHECK) |
| `place_sources` | place_id, title, url, type, position | type: article, video, instagram, official |
| `place_photos` | place_id, object_key, width, height, alt, credit, license, source_url, position | license: own(직접 찍음), press(언론·공식 배포용), credited(공개된 사진을 출처 표기로 씀). position 0이 대표 사진 |
| `place_embeds` | place_id, type, url, position | type: youtube, instagram. 공개 게시물만 |

### 나머지 테이블

| 테이블 | 주요 컬럼 | 규칙 |
| --- | --- | --- |
| `makers` | slug, name, kind, region, intro, website, instagram, affiliation_id, slug_locked_at | kind: person, studio, owner(이름을 밝히지 않은 주인). affiliation_id는 소속 스튜디오. 공개된 공간에 연결되면 slug가 잠김 |
| `daily_picks` | pick_date PK, place_id unique, line(40) | 월~금만(DB CHECK). 같은 공간은 한 번만. published 공간만 |
| `users` | provider, provider_id, email, nickname(20), profile_image_url, role, following_seen_at | (provider, provider_id) unique. role: user, admin. following_seen_at: 팔로잉 탭을 마지막으로 본 시각 |
| `saves` | user_id, place_id, status, updated_at | PK(user_id, place_id). 같은 버튼을 다시 누르면 행 삭제 |
| `follows` | user_id, maker_id, created_at | PK(user_id, maker_id) |
| `credit_suggestions` | user_id, place_id, role, maker_name, source_url, is_self, status, reviewed_at | status: pending, accepted, declined |

로그인 세션은 Spring Session이 만드는 테이블에 저장합니다. `llm_calls`는 AI 초안을 붙일 때 쓸 테이블이라 지금은 비어 있습니다(11절).

**제보 한도**: 공간 제보와 크레딧 제보를 합쳐 사용자당 하루(KST 자정 기준) 10건.

**탈퇴**: 사용자의 세션을 지우고 `users` 행을 삭제합니다. `saves`와 `follows`는 함께 지워지고(FK CASCADE), 제보한 공간과 크레딧 제보는 남기되 작성자만 비웁니다(FK SET NULL).

## 5. 화면 목록과 URL

| URL | 화면 | 로그인 |
| --- | --- | --- |
| `/` | 홈: 오늘의 공간 피드 | — |
| `/places` | 둘러보기: 공간 | — |
| `/makers` | 둘러보기: 만든 사람 | — |
| `/places/[slug]` | 공간 상세 | 저장 버튼만 |
| `/makers/[slug]` | 만든 사람 프로필 | 팔로우 버튼만 |
| `/me` | 내 공간 | 필요 |
| `/suggest` | 공간 소개하기 | 필요 |
| `/admin` | 관리자 홈 | 관리자 |
| `/admin/places`, `/admin/places/new`, `/admin/places/[id]`, `/admin/places/[id]/preview` | 공간 목록·등록·수정·미리보기 | 관리자 |
| `/admin/makers`, `/admin/makers/[id]` | 만든 사람 목록·수정 | 관리자 |
| `/admin/picks` | 오늘의 공간 편성 | 관리자 |
| `/admin/suggestions` | 제보 검토 | 관리자 |
| `/about`, `/privacy`, `/terms` | 소개, 개인정보처리방침, 이용약관 | — |

공개 화면은 서버에서 그리고 캐시합니다. 관리자가 공개·수정하면 바뀐 페이지의 캐시만 지웁니다([DECISIONS.md 6절](DECISIONS.md#6-프론트엔드--nextjs-16-app-router--typescript)). 로그인 뒤 화면과 관리자 화면은 브라우저에서 그립니다.

하단 탭 바는 **오늘 · 둘러보기 · 내 공간**입니다. 관리자 화면에는 탭 바가 없습니다. 로그인 사용자의 팔로잉 탭에 "새로운" 공간이 하나라도 있으면 내 공간 옆에 작은 점을 띄웁니다(알림 발송 없음). 로그인은 별도 페이지 없이 바텀 시트로 띄웁니다.

## 6. 화면별 동작

### 공통: 저장 버튼

- 두 버튼: **가고 싶어요**, **다녀왔어요**. 한 번에 하나만 켜집니다.
- 켜진 버튼을 다시 누르면 꺼집니다(저장 해제). 다른 버튼을 누르면 상태가 바뀝니다.
- 누른 즉시 화면에 반영하고, 실패하면 되돌린 뒤 "저장하지 못했어요. 다시 시도해 주세요" 토스트를 띄웁니다.
- 로그인하지 않았으면 로그인 시트를 띄우고, 로그인한 뒤 누른 동작을 이어서 끝냅니다.

### 공통: 팔로우 버튼

- 만든 사람 프로필과 공간 상세의 크레딧 줄에 있습니다. "팔로우" ⇄ "팔로잉".
- 동작 규칙은 저장 버튼과 같습니다.
- 프로필이 없는 만든 사람(`slug`가 없음)에게는 팔로우 버튼을 두지 않고, 이름에도 링크를 걸지 않습니다.

### 공통: 로그인 시트

- "저장하려면 로그인이 필요해요"(동작에 따라 "팔로우하려면", "소개하려면").
- 버튼은 Google로 계속하기. 아래에 이용약관·개인정보처리방침 링크.
- "만 14세 이상입니다"를 확인해야 버튼이 켜집니다.
- 로그인한 뒤 원래 보던 화면으로 돌아옵니다.

### 홈 `/` — 오늘의 공간 피드

- **카드 한 장 = 화면 전체.** 대표 사진 한 장, 요일("수요일의 공간"), 공간 이름, 지역, 에디터의 한 줄, 만든 사람 이름, 저장 버튼.
- **세로로 넘겨** 다음 카드로 갑니다. 상단에 그 카드의 주 안 순서를 표시합니다(수요일 카드면 03 / 05).
- 순서는 오늘 공간이 맨 위, 그 아래로 어제, 그제 순입니다.
- 카드를 누르면 공간 상세로 갑니다. 뒤로 가면 보던 카드로 돌아옵니다. 만든 사람 이름을 누르면 프로필로 갑니다.
- 팔로우 표시는 인스타그램 방식입니다. 아직 팔로우하지 않은 만든 사람이면 이름 옆에 작은 "팔로우" 버튼을 띄우고, 이미 팔로우했으면 이름만 둡니다. 로그인하지 않았으면 모두 "팔로우"로 보입니다. 크레딧이 여럿이면 첫 번째 한 명만 보여 줍니다.
- 카드에서는 사진을 한 장만 보여 줍니다. 세로 넘기기와 가로 손동작이 섞이지 않게 하기 위해서입니다.
- **마지막 화면**은 제목 한 줄과 안내 한 줄입니다. 다음 공개가 언제인지에 따라 셋 중 하나이고, 어느 것인지는 서버가 정해 줍니다(API의 `nextRelative`). 버튼은 **전체 둘러보기**, **뉴스레터 구독** 두 개입니다.

    | 경우 | `nextRelative` | 제목 | 안내 |
    | --- | --- | --- | --- |
    | 평일 오전 8시 전(다음 공개가 오늘) | `today` | 오늘의 공간은 아직이에요. | 오전 8시에 열려요. |
    | 다음 공개가 내일(월~목 8시 이후, 일요일) | `tomorrow` | 오늘은 여기까지예요. | 내일은 ○요일의 공간이 와요. |
    | 그 밖(금요일 8시 이후, 토요일) | `later` | 이번 주는 여기까지예요. | 월요일 오전 8시에 새 공간이 와요. |

- 월요일 8시 전에는 지난주 다섯 곳을 보여 줍니다.
- 이번 주에 열린 공간이 없으면 마지막 화면만 보여 줍니다.

### 둘러보기 `/places`, `/makers`

- 상단 탭: **공간 | 만든 사람**.
- 공간: 3열 사진 격자. 종류 필터(여러 개 선택). 정렬은 최근 공개순 하나. 필터는 URL 쿼리(`?kind=garden`)에 남깁니다.
- 만든 사람: 이름, 종류, 대표 공간 사진 한 장의 목록. 공개된 공간이 있는 사람만.
- 폐업 공간은 목록에서 빠집니다. 휴업 공간은 남기고 "휴업 중"을 붙입니다. 이 캡션은 모든 격자(둘러보기, 만든 사람 프로필, 같은 만든 사람의 다른 공간, 내 공간)에 붙입니다.
- 결과가 없으면 "아직 이 조건의 공간이 없어요" + 필터 초기화 + 공간 소개하기.

### 공간 상세 `/places/[slug]`

1. 사진(옆으로 넘기기, 사진마다 아래에 "사진: ○○") 또는 임베드
2. 이름, 지역·종류, "머물러 봄" 배지 또는 "○○으로 만남"
3. 저장 버튼 두 개, 공유
4. 에디터의 감상
5. 감각의 기록(빈 항목은 줄째 숨김, 넷 다 비면 영역 숨김)
6. 만든 사람들: 역할 · 이름(프로필 링크) · 팔로우 · 확인됨이면 출처 링크, 아니면 "확인 중". 맨 아래 "이 공간을 만드셨나요? 크레딧을 알려주세요"
7. 에세이(있을 때만)
8. 방문 정보: 주소(복사), 방문 방식, 방문 메모, 네이버지도·카카오맵 링크
9. 같은 만든 사람의 다른 공간(최대 6곳, 3열 격자)

- 휴업이면 상단에 "지금은 쉬고 있어요". 폐업이면 페이지는 두고 "이제는 만날 수 없는 공간이에요"를 띄우고 저장 버튼을 숨깁니다(이미 저장한 기록은 유지). 공개되지 않은 slug는 404입니다.

### 만든 사람 프로필 `/makers/[slug]`

- 위: 이름, 종류(개인/스튜디오), 소개, 웹사이트·인스타그램 링크, 팔로우 버튼, 소속 스튜디오 링크.
- 아래: 이 사람이 크레딧에 있는 공간의 3열 사진 격자, 최근 공개순. 사진 위에 역할을 작게(예: "조경").
- 폐업 공간도 격자에 남기고 흐리게 + "폐업". 만든 사람의 작업 이력이기 때문입니다.

### 내 공간 `/me`

- 탭: **가고 싶어요 · 다녀왔어요 · 팔로잉**.
- 가고 싶어요·다녀왔어요: 3열 격자, 최근 저장순.
- 팔로잉: 위에 **"팔로우한 사람들의 공간"**(기간 제한 없이 전체, 공개 최신순, 3열 격자, 사진 위에 만든 사람 이름), 아래에 팔로우한 만든 사람 목록.
    - 팔로잉 탭을 마지막으로 본 뒤에, 그리고 그 공간의 만든 사람을 팔로우한 뒤에 공개된 공간에 **"새로운"** 표시를 붙입니다. 늦게 팔로우한 사람의 지난 공간은 새롭지 않습니다. 팔로우한 사람이 여럿인 공간은 그중 한 명 기준으로라도 새로우면 "새로운"입니다. 탭을 연 적이 없으면 팔로우 시각만 봅니다.
    - 팔로잉 탭을 열면 마지막으로 본 시각을 지금으로 바꿉니다. "새로운" 표시는 그 화면을 떠날 때까지 유지합니다.
    - 같은 공간이 팔로우한 여러 사람의 작업이면 한 번만 보여 줍니다.
- "내가 소개한 공간": 탭 위의 한 줄 링크로 시트를 열어 제보 상태(검토 중 / 소개됨 / 보류)를 보여 줍니다. 제보가 없으면 링크를 그리지 않습니다.
- 저장한 공간이 없으면 "아직 저장한 공간이 없어요" + 오늘의 공간 보기.
- 상단 메뉴: 닉네임 수정, 로그아웃, 탈퇴(확인을 한 번 더 받음).

### 공간 소개하기 `/suggest`

- 입력: 공간 이름(필수), 지역(필수), 참고 링크(선택), "이 공간이 오래 생각나는 이유"(필수, 300자), 만든 사람을 아는지(선택).
- 제출하면 `places`에 `suggested` 상태로 저장하고 "고마워요. 읽어보고 소개되면 알려드릴게요."를 보여 줍니다.
- 같은 이름의 공개된 공간이 있으면 서버가 저장하지 않고 "이미 소개된 공간이에요"와 그 공간 링크를 돌려줍니다.

### 크레딧 알려주기 (공간 상세의 시트)

- 입력: 역할, 이름, 출처 링크, "제가 만든 사람이에요" 체크. `credit_suggestions`에 저장합니다.

## 7. 관리자 화면

권한은 `role = admin`만 있습니다. 다른 사용자가 관리자 API를 부르면 403입니다.

### 관리자 홈 `/admin`

- 이번 주·다음 주 편성 현황(월~금 5칸, 빈 칸 강조), 검토 대기 제보 수, 작성 중인 공간 수, 이번 달 AI 비용(AI 초안을 붙이기 전까지는 0).

### 공간 목록 `/admin/places`

- 상태 필터(제보됨, 작성 중, 공개, 휴업, 폐업, 반려), 이름 검색, 최근 수정순.

### 공간 등록·수정 `/admin/places/new`, `/admin/places/[id]`

- 새 공간은 이름(필요하면 지역)만으로 먼저 만들고, 나머지를 채워 공개합니다.
- **묶음**: 기본 정보(이름, slug, 종류, 지역, 주소) · 방문 정보 · 감상과 감각 · 크레딧 · 출처와 임베드 · 사진 · 에세이 · 상태.
- **큰 버튼 하나**: 작성 중이고 공개 조건이 다 찼으면 "저장하고 공개", 그 밖에는 "저장"입니다. 처리 중일 때만 꺼집니다. 공개 조건이 모자라면 누른 뒤 빈 칸 옆에 이유를 보여 줍니다. 공개·휴업 중인 공간에서 필수 칸을 비우면 저장되지 않습니다.
- **⋯ 메뉴**: 미리보기(새 탭으로 `/admin/places/[id]/preview`, 저장된 내용을 공개 상세 화면 그대로 보여 줌)와 휴업·폐업 같은 상태 변경이 있습니다. 저장하지 않은 변경이 있으면 "먼저 저장해 주세요"로 꺼집니다.
- **서버 자동 저장은 없습니다.** 저장하지 않은 입력은 공간마다 브라우저에 보관해, 폼을 다시 열면 불러옵니다.
- **검증**: 글자 수, slug 형식·중복, 공개 시 필수 항목. 프론트와 백엔드가 같은 규칙입니다. 실패하면 항목 옆에 이유를 보여 줍니다.
- **slug**는 공개 전에만 바꿀 수 있습니다.
- **크레딧**: 만든 사람을 이름으로 검색해 고르고, 없으면 그 자리에서 새로 만듭니다. 역할, 확인 여부, 출처 URL을 적고 순서를 바꿀 수 있습니다.
- **사진**: 브라우저가 WebP 두 크기(1600px, 800px)로 바꿔 R2에 직접 올리고, 서버에 사진 정보를 등록합니다. 등록되지 않은 채 24시간이 지난 파일은 정리 작업이 지웁니다. 순서는 [README의 사진 업로드 흐름](../README.md#사진-업로드), 경로와 제한은 [API.md](API.md#사진)에 있습니다.

### 만든 사람 `/admin/makers`

- 목록(이름 검색), 수정 폼(slug, 이름, 종류, 지역, 소개, 링크, 소속). slug는 공개된 공간에 연결된 뒤 잠깁니다.

### 오늘의 공간 편성 `/admin/picks`

- 이번 주와 다음 주의 월~금 칸. 칸마다 공개된 공간을 골라 넣고 한 줄 소개(40자)를 씁니다.
- 이미 편성된 공간은 고를 수 없습니다. 지난 날짜와, 08:00이 지난 오늘 칸은 바꿀 수 없습니다.
- 공개 여부를 시각으로 계산하므로, 편성은 그날 8시가 되어야 피드에 나타납니다.

### 제보 검토 `/admin/suggestions`

- 공간 제보: **작성 시작**(draft로 바꾸고 등록 폼 열기) 또는 **반려**.
- 크레딧 제보: **반영**(그 공간 크레딧에 추가) 또는 **반려**.

어떤 변경이 어떤 페이지를 다시 만드는지는 [API.md "재생성 호출"](API.md#spring--next-post-revalidate_urlapirevalidate)에 있습니다.

## 8. 콘텐츠·운영 규칙

공간 하나를 등록하는 데 30분 이내가 목표입니다.

### 등록 기준 (모두 충족해야 공개)

- 다녀온 뒤에도 오래 생각나는 곳인가(또는 그럴 거라고 확신하는가)
- 일반인이 방문할 수 있는가(개인 주택·사무실 제외. 예약·입장권·숙박은 가능)
- 만든 사람을 출처와 함께 1명 이상 밝힐 수 있는가
- 공식 인스타그램 공개 게시물(임베드) 또는 출처를 표기할 수 있는 사진이 있는가
- 최근 3개월 안에 운영 중인 흔적이 있는가

### 등록 흐름

1. 공간 이름으로 새 공간을 만든다
2. 주소와 크레딧을 출처에서 확인해 채운다
3. 감상, 감각, 한 줄 소개를 직접 쓴다
4. 사진: 공식 인스타그램 공개 게시물이 있으면 임베드를 우선한다. 사진을 올리면 직접 찍은 것(`own`)이거나 출처 이름과 링크를 함께 적는다(`press` · `credited`)
5. 공개한다
6. 편성 칸에 넣는다

### 운영 리듬

| 언제 | 무엇 |
| --- | --- |
| 주말 | 다음 주 다섯 곳 등록·편성 |
| 월~금 08:00 | 자동 공개. 인스타그램에 같은 공간 하나 게시(계획) |
| 금요일 18:00 | 그 주 다섯 곳 뉴스레터 발송(계획) |
| 주 1회 | 제보 검토 |
| 월 1회 | 전체 공간 운영 상태 점검(휴업·폐업 반영) |

### 사진

- 사용 허락을 따로 받는 절차는 두지 않습니다. 대신 모든 사진 아래 "사진: ○○"과 출처 링크를 표기합니다(`credit`, `source_url`). `license`가 `own`이 아니면 `source_url`이 필수입니다.
- 공식 인스타그램 공개 게시물이 있으면 사진 대신 임베드를 우선합니다.
- 삭제 요청은 48시간 안에 내립니다. 요청 창구는 `/about`의 이메일입니다.

### 크레딧 제보 반영 기준

| 제보 | 기준 | 결과 |
| --- | --- | --- |
| 출처 있음 | 출처에서 확인됨 | verified로 반영 |
| 본인이라고 밝힘 | 공식 계정·웹사이트에서 작업 확인됨 | verified, 출처는 그 페이지 |
| 확인 불가 | — | 확인 중으로 반영하거나 반려 |

### 뉴스레터 비용 기준

- 메일리 무료 요금제는 월 1,000통 또는 4회 발행까지입니다. 주 1회 발송이면 구독자 약 250명까지 무료입니다.
- 250명을 넘으면 유료 요금제(월 6,900원부터)와 격주 발송 중 하나를 고릅니다.
- 직접 발송은 수신 거부와 발송 실패 처리를 직접 만들어야 해서 쓰지 않습니다.

### 로그인

- 구글 scope는 `openid`, `email`, `profile`만 씁니다. OAuth 앱은 "프로덕션"으로 게시합니다(테스트 모드는 동의가 7일마다 만료됩니다).
- 계정은 `(provider, provider_id)`로 구분합니다. 같은 이메일이라도 제공자가 다르면 다른 계정입니다.
- 세션 쿠키는 HttpOnly · SameSite=Lax이고, 운영에서는 Secure입니다.

### 서비스 이름과 검색 노출

- 정식 이름은 **"공간의 지은이"**, 줄여 부를 때 **"지은이"**입니다. "지은이"만으로는 모든 책 정보에 나오는 단어라 검색에 묻히므로, 검색에 걸리는 곳에는 정식 이름을 씁니다.
- 페이지 제목: `<공간 이름> — 공간의 지은이`, `<만든 사람 이름>의 공간들 — 공간의 지은이`, 홈은 `공간의 지은이 — 오늘의 공간`.
- 도메인은 `jieuni.space`입니다.
- 유입 대부분은 서비스 이름이 아니라 공간·만든 사람 이름 검색에서 옵니다. 그래서 이 두 페이지의 제목, 설명, 본문이 검색 노출의 핵심입니다.
- 구글 서치 콘솔과 네이버 서치어드바이저에 등록하고 sitemap을 제출합니다.

### 공유 카드

- 공간과 만든 사람 페이지마다 제목·설명·공유 카드(1200×630)를 둡니다. `sitemap.xml`을 만듭니다.
- 공유 카드에는 글자만 넣습니다. 사진이 모두 WebP인데 카드를 그리는 도구(satori)가 WebP를 그리지 못하기 때문입니다.

### 성능·접근성

- 목표: 모바일에서 공간 상세 첫 사진이 2.5초 안에 보여야 합니다. 사진은 미리 변환한 WebP를 쓰고, 임베드는 누를 때만 불러옵니다.
- 지금 모바일 LCP는 5.2초로 아직 맞추지 못했습니다. 원인은 한글 웹폰트 선언 CSS로 보고 있습니다.
- 모든 사진에 `alt`가 있어야 합니다(공개할 때 검사). 누르는 요소는 44px 이상입니다.

### 개인정보

- 이메일과 닉네임을 받으므로 개인정보 처리방침을 공개합니다(개인정보 보호법 제30조). 처리 목적·항목·보관 기간, 파기, 안전 조치, 열람 청구 방법을 담습니다.
- 만 14세 미만은 받지 않습니다.

## 10. 개발용 시드

`seed/seed.json`은 **개발용 가짜 데이터**입니다. 이름, 주소, 링크가 모두 지어낸 값이고, 사진은 없습니다(화면에는 사진 자리 색이 보입니다).

- `dev` 프로필로 뜬 서버가 시작할 때 `makers` 테이블이 비어 있으면 이 파일을 한 트랜잭션으로 넣고, 행이 있으면 건너뜁니다. 다시 띄워도 중복되지 않습니다. 운영 프로필에는 이 코드가 없습니다.
- 공간 다섯 곳으로 화면이 다뤄야 할 경우를 덮습니다: 공간 3곳 이상에 크레딧이 있는 만든 사람, 크레딧이 여러 개인 공간, 감각 일부를 비운 공간, 폐업 공간, 이번 주와 지난주 편성.
- 날짜는 넣은 시각을 기준으로 적습니다. 공간마다 `publishedDaysAgo`(며칠 전에 공개됐나)를 두고, 편성은 `picks: [{ weeksAgo, weekday, place, line }]`처럼 "몇 주 전 무슨 요일"로 적어 언제 넣어도 이번 주·지난주 칸에 들어갑니다.
- 편성은 이번 주 월·화·수와 지난주 목·금 다섯 칸입니다. 07:59/08:00 경계, 월요일 8시 전의 지난주, 편성 빈 날(이번 주 목·금)을 함께 확인할 수 있습니다.

```json
{
  "makers": [
    { "slug": "garden-dal", "name": "정원 달", "kind": "studio", "region": "경기 양평군",
      "intro": "(가짜) 계절이 바뀌는 속도로 정원을 가꾸는 조경 스튜디오." }
  ],
  "places": [
    { "slug": "quiet-hill-garden", "name": "고요언덕 정원", "kind": "garden", "region": "경기 양평군",
      "access": "ticket", "status": "published", "publishedDaysAgo": 30,
      "credits": [ { "maker": "garden-dal", "role": "landscape", "verified": true, "sourceUrl": "https://example.com/articles/quiet-hill" } ] }
  ],
  "picks": [ { "weeksAgo": 0, "weekday": "WEDNESDAY", "place": "quiet-hill-garden", "line": "(자리 표시) 수요일의 한 줄" } ]
}
```

위 예시는 형식을 보여 주려고 줄인 것입니다. 실제 필드는 파일을 보세요.

## 11. 공개 뒤 계획

아래는 아직 만들지 않은 기능입니다. 코드에는 자리만 있거나 없습니다.

### AI 초안 채우기

관리자 폼에서 공간 이름을 넣으면, 웹을 조사해 사실 항목을 미리 채우는 기능입니다.

- **채우는 것**: 주소, 좌표, 종류, 방문 방식, 크레딧 후보, 출처 후보. 항목마다 근거 URL을 붙이고, 근거가 없으면 비웁니다.
- **채우지 않는 것**: 감상, 감각, 한 줄 소개, 에세이. 응답에 이 필드가 있어도 서버가 버립니다.
- 폼에는 "AI 제안" 표시와 함께 채워지고, 관리자가 항목별로 받아들이거나 지웁니다. 받아들이기 전에는 저장되지 않습니다.
- 사람이 하는 일: 등록 여부 판단, 크레딧 확인, 감상·감각·한 줄·에세이 쓰기, 편성.
- **구조**: Python(FastAPI) 서비스를 따로 두고 Spring이 내부망으로만 부릅니다. Tool Calling 루프를 프레임워크 없이 먼저 만들고, 같은 흐름을 LangGraph로 옮겨 비교합니다. 같은 도구를 MCP 서버로도 감쌉니다.
- **도구**: 웹 검색(Tavily), 페이지 읽기, 주소 검색(카카오 로컬). 검색 결과는 저장하지 않고 그 호출 안에서만 씁니다.
- **평가**: 크레딧이 확인된 공간 20곳을 정답으로 두고 필드별 정확도, 근거 URL 일치율, 지어낸 값 비율, 건당 비용·시간을 잽니다. 비용이 들어 CI에서는 돌리지 않습니다.
- **기록**: 호출마다 `llm_calls`에 모델, 토큰, 비용, 지연, 재시도, 성공 여부를 남기고, 관리자 화면 "AI 기록"(`/admin/llm`)에서 봅니다. 관리자 메뉴에는 이 항목이 꺼진 상태로 있습니다.
