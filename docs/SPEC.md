### 두 목표

1. **공간에서 감동받는 사람을 모은다.**
2. **풀스택 역량을 보여주고, 만들면서 배운다.** 로그인, 권한, CRUD, 파일 업로드, 예약 공개, AI 연동, 배포.

둘은 같은 무게다. 서비스의 조용한 결을 해치지 않는 한, 2번에 필요한 기능은 넣는다.

### 결정 원칙

1. "이 공간은 다녀온 뒤에도 오래 생각나는가?"에 도움이 되는 쪽을 고른다.
2. 바꾸기 비싼 것(데이터 구조, URL, 로그인 방식)만 지금 확정한다. 문구와 색은 가정으로 두고 진행한다.
3. 혼자 운영할 수 있는 쪽을 고른다.
4. 설명할 수 있는 코드만 넣는다.

### D4. 하루 한 곳 피드

- 월요일부터 금요일까지 매일 **오전 8시(KST)**에 공간 한 곳이 열린다. 한 주에 딱 5곳.
- 피드에는 **이번 주에 지금까지 열린 공간**만 나온다. 수요일 오후라면 월·화·수 3곳.
- 주말에는 새 공간이 없고 그 주 5곳이 그대로 보인다. 금요일 저녁에 그 주 5곳을 뉴스레터로 묶어 보낸다.
- 예약된 공간이 없는 날은 그냥 비운다. 시스템이 아무 공간이나 대신 채우지 않는다.
- 이유: 하루 한 곳이라 조용한 결과 맞고, 매일 다시 올 이유가 생긴다. 매일 오지 않는 사람은 쌓인 공간을 몰아 본다. 인스타그램에 하루 한 곳 올리는 리듬과도 맞다.

### D5. 공간 콘텐츠는 DB와 관리자 폼으로

- v0.1의 파일 방식은 Supabase 일시 정지와 관리자 화면 부담 때문이었다. DB를 직접 운영하면서 첫 이유가 사라졌고, 관리자 화면은 풀스택 역량을 보여줄 핵심이 됐다.
- 공개 페이지는 정적으로 빠르게 보여주고, 관리자가 수정·공개하면 해당 페이지만 다시 만든다.
- 공간과 만든 사람의 `slug`는 처음 공개한 뒤 바꿀 수 없다. 폐업한 공간도 지우지 않는다.

### D11·D12. 인스타에서 가져오는 것과 버리는 것

| 인스타 요소 | 결정 |
| --- | --- |
| 프로필 + 3열 사진 격자 | 가져옴 → 만든 사람 프로필 |
| 사진 옆으로 넘기기 | 가져옴 → 공간 상세 |
| 저장(북마크) | 가져옴 → 가고 싶어요 / 다녀왔어요 |
| 하단 탭 바 | 가져옴 → 오늘 · 둘러보기 · 내 공간 |
| 끝없는 피드 | 버림 → 끝이 있는 하루 한 곳 피드 |
| 좋아요, 숫자 | 버림 |
| 댓글, DM, 스토리 | 버림 |

## 3. 데이터 모델

모든 데이터는 PostgreSQL 하나에 둔다. 스키마는 Flyway 마이그레이션으로만 바꾼다.

### 원칙: "필수"는 공개할 때 검사한다

제보된 공간은 이름과 지역뿐이고 작성 중인 공간도 빈칸이 많다. 그래서 DB의 NOT NULL은 최소한으로 두고, **`published`로 바꿀 때 필수 항목을 서버가 검사**한다. 관리자 폼도 같은 규칙으로 검사한다.

### `places`

| --- | --- | --- | --- |
| `id` | bigint PK | — | |
| `slug` | varchar unique | ✓ | 영문 소문자·숫자·하이픈. 처음 공개 후 변경 불가 |

**공개 시 추가 검사**: 출처 있는 크레딧 1개 이상 · 사진 1장 이상 또는 임베드 1개 이상 · "머물러 봄"이 없으면 출처 1개 이상 · 모든 사진에 `alt`와 `credit`, `license`가 `own`이 아닌 사진에는 `source_url`.

**상태 전환**: suggested → draft 또는 rejected · draft → published · published ⇄ paused · published·paused → closed. published에서 draft로 되돌리지 않는다(저장한 사용자가 있기 때문). 내리려면 closed.

## 4. 화면 목록과 URL

공개 화면은 모바일 기준(375px). 데스크톱에서는 본문을 최대 480px로 가운데 둔다. **관리자 화면만 데스크톱 너비(최대 960px)를 허용**한다. URL은 한 번 공개하면 바꾸지 않는다.

| URL | 화면 | 로그인 | 렌더링 |
| --- | --- | --- | --- |
| `/` | 홈: 오늘의 공간 피드 | — | 정적. 매일 08:00 재생성 |
| `/places` | 둘러보기: 공간 | — | 정적 |
| `/makers` | 둘러보기: 만든 사람 | — | 정적 |
| `/places/[slug]` | 공간 상세 | 저장 버튼만 | 정적. 수정·공개 시 재생성 |
| `/makers/[slug]` | 만든 사람 프로필 | 팔로우 버튼만 | 정적. 수정·공개 시 재생성 |
| `/me` | 내 공간 | 필요 | 클라이언트 |

## 5. 화면별 동작

### 공통: 저장 버튼

- 두 버튼: **가고 싶어요**, **다녀왔어요**. 한 번에 하나만 켜진다.
- 켜진 버튼을 다시 누르면 꺼진다(저장 해제). 다른 버튼을 누르면 상태가 바뀐다.
- 누른 즉시 화면에 반영하고(낙관적 업데이트), 실패하면 되돌리고 "저장하지 못했어요. 다시 시도해 주세요" 토스트.
- 로그인하지 않았으면 로그인 시트를 띄우고, 로그인 후 누른 동작을 이어서 완료한다.
- 저장 수는 어디에도 표시하지 않는다.

### 공통: 팔로우 버튼

- 만든 사람 프로필과 공간 상세의 크레딧 줄에 있다. "팔로우" ⇄ "팔로잉".
- 동작 규칙은 저장 버튼과 같다. 팔로워 수는 표시하지 않는다.

### 공통: 로그인 시트

- "저장하려면 로그인이 필요해요"(동작에 따라 "팔로우하려면", "소개하려면").
- 버튼: Google로 계속하기. 아래에 이용약관·개인정보처리방침 링크.
- 첫 로그인이면 "만 14세 이상입니다" 확인 후 가입.
- 로그인 후 원래 보던 화면으로 돌아온다.

### 홈 `/` — 오늘의 공간 피드

- **카드 한 장 = 화면 전체.** 대표 사진 한 장, 요일("수요일의 공간"), 공간 이름, 지역, 에디터의 한 줄(`daily_picks.line`), 만든 사람 이름, 저장 버튼.
- **세로로 넘겨** 다음 카드로 간다. 상단에 진행 표시: 그 카드 요일의 주 안 순서 / 05(수요일 카드면 03 / 05).
- 순서는 **오늘 공간이 맨 위**, 그 아래로 어제, 그제 순.
- **카드를 누르면** 공간 상세로 간다. 뒤로 가면 보던 카드로 돌아온다.
- **만든 사람 이름을 누르면** 만든 사람 프로필로 간다.
- **팔로우 표시는 인스타 방식**: 아직 팔로우하지 않은 만든 사람이면 이름 옆에 작은 **"팔로우"** 버튼을 띄우고, 이미 팔로우했으면 이름만 둔다("팔로잉" 표시 없음). 로그인하지 않았으면 모두 "팔로우"로 보이고, 누르면 로그인 시트가 뜬다. 크레딧이 여러 명이면 카드에는 첫 번째 크레딧 한 명만 보여준다.
- 피드 카드에서는 사진을 한 장만 보여준다. 세로 넘기기와 손동작이 섞이지 않게 하기 위해서다.
- **마지막 화면**: 제목 한 줄과 안내 한 줄의 짝. 다음 공개가 언제인지에 따라 셋 중 하나다. 버튼은 **전체 둘러보기**, **뉴스레터 구독** 두 개.

    | 경우 | `nextRelative` | 제목 | 안내 |
    | --- | --- | --- | --- |
    | 평일 오전 8시 전(다음 공개가 오늘) | `today` | 오늘의 공간은 아직이에요. | 오전 8시에 열려요. |
    | 다음 공개가 내일(월~목 8시 이후, 일요일) | `tomorrow` | 오늘은 여기까지예요. | 내일은 ○요일의 공간이 와요. |
    | 그 밖(금요일 8시 이후, 토요일) | `later` | 이번 주는 여기까지예요. | 월요일 오전 8시에 새 공간이 와요. |

    - 셋 중 무엇인지는 서버가 정해 준다(API.md 1절 `nextRelative`). ○요일은 `nextWeekday`. 프론트는 시간을 계산하지 않는다.
- **월요일 8시 전**: 지난주 5곳을 보여준다(새 주가 열리기 전까지).
- 이번 주에 열린 공간이 없으면(편성 누락): 마지막 화면만 보여준다.

### 둘러보기 `/places`, `/makers`

- 상단 탭: **공간 | 만든 사람**.
- 공간: 3열 사진 격자. 종류 필터(다중 선택). 정렬은 최근 공개순 하나. 필터는 URL 쿼리(`?kind=garden`)에 남긴다.
- 만든 사람: 이름, 종류, 대표 공간 사진 한 장의 목록. 공개된 공간이 있는 사람만.
- 폐업 공간은 목록에서 빠진다. 휴업은 남기고 "휴업 중".
- 빈 결과: "아직 이 조건의 공간이 없어요" + 필터 초기화 + 공간 소개하기.

### 공간 상세 `/places/[slug]`

1. 사진(옆으로 넘기기, 사진마다 아래에 "사진: ○○") 또는 임베드
2. 이름, 지역·종류, "머물러 봄" 배지 또는 "○○으로 만남"
3. 저장 버튼 두 개, 공유
4. 에디터의 감상
5. 감각의 기록(빈 항목은 줄째 숨김, 넷 다 비면 영역 숨김)
6. 만든 사람들: 역할 · 이름(프로필 링크) · 팔로우 · 확인됨이면 출처 아이콘, 아니면 "확인 중". 맨 아래 "이 공간을 만드셨나요? 크레딧을 알려주세요"
7. 에세이(있을 때만)
8. 방문 정보: 주소(복사), 방문 방식, 방문 메모, 네이버지도·카카오맵 링크
9. 같은 만든 사람의 다른 공간(최대 6곳, 3열 격자)

- 휴업: 상단에 "지금은 쉬고 있어요". 폐업: 페이지는 유지하고 "이제는 만날 수 없는 공간이에요", 저장 버튼 숨김(이미 저장한 기록은 유지). 공개되지 않은 slug는 404.

### 만든 사람 프로필 `/makers/[slug]`

- 위: 이름, 종류(개인/스튜디오), 소개, 웹사이트·인스타 링크, 팔로우 버튼, 소속 스튜디오 링크.
- 아래: 이 사람이 크레딧에 있는 공간의 **3열 사진 격자**, 최근 공개순. 사진 위에 역할을 작게(예: "조경").
- 폐업 공간도 격자에 남기고 흐리게 + "폐업". 만든 사람의 작업 이력이기 때문이다.

### 내 공간 `/me`

- 탭: **가고 싶어요 · 다녀왔어요 · 팔로잉**.
- 가고 싶어요·다녀왔어요: 3열 격자, 최근 저장순.
- 팔로잉: 위에 **"팔로우한 사람들의 공간"**(기간 제한 없이 전체, 공개 최신순, 3열 격자, 사진 위에 만든 사람 이름), 아래에 팔로우한 만든 사람 목록.
    - 이 탭을 마지막으로 본 시각(`users.following_seen_at`) 이후에 공개된 공간에는 **"새로운"** 표시를 붙인다.
    - 팔로잉 탭을 열면 `following_seen_at`을 지금으로 갱신한다. "새로운" 표시는 그 화면을 떠날 때까지 유지한다.
    - 같은 공간이 팔로우한 여러 사람의 작업이면 한 번만 보여준다.
- "내가 소개한 공간": 제보 상태(검토 중 / 소개됨 / 보류) 목록. 제보가 없으면 숨김.
- 빈 상태: "아직 저장한 공간이 없어요" + 오늘의 공간 보기.
- 상단 메뉴: 닉네임 수정, 로그아웃, 탈퇴(확인 모달).

### 공간 소개하기 `/suggest`

- 입력: 공간 이름(필수), 지역(필수), 참고 링크(선택), "이 공간이 오래 생각나는 이유"(필수, 300자), 만든 사람을 아는지(선택).
- 제출하면 `places`에 `suggested` 상태로 저장. "고마워요. 읽어보고 소개되면 알려드릴게요."
- 같은 이름의 공개된 공간이 있으면 제출 전에 "이미 소개된 공간이에요" + 링크.

### 크레딧 알려주기 (공간 상세의 시트)

- 입력: 역할, 이름, 출처 링크, "제가 만든 사람이에요" 체크. `credit_suggestions`에 저장.

## 6. 관리자 화면

권한: `role = admin`만. 다른 사용자가 `/admin` API를 부르면 403.

### 관리자 홈 `/admin`

- 이번 주·다음 주 편성 현황(월~금 5칸, 빈 칸 강조), 검토 대기 제보 수, 작성 중인 공간 수, 이번 달 AI 비용.

### 공간 목록 `/admin/places`

- 상태 필터(제보됨, 작성 중, 공개, 휴업, 폐업, 반려), 이름 검색, 최근 수정순.

### 공간 등록·수정 `/admin/places/new`, `/admin/places/[id]`

- **묶음**: 기본 정보(이름, slug, 종류, 지역, 주소, 좌표) · 방문 정보 · 감상과 감각 · 크레딧 · 출처와 임베드 · 사진 · 에세이 · 상태.
- **버튼**: 임시저장(언제나 가능), 미리보기, 공개(공개 시 검사 통과해야 활성), 휴업·폐업.
- **검증**: 글자 수, slug 형식·중복, 공개 시 필수 항목. 프론트와 백엔드가 같은 규칙. 실패하면 항목 옆에 이유.
- **slug**는 공개 전에만 수정 가능. 공개 후에는 잠긴다.
- **크레딧**: 만든 사람을 이름으로 검색해 고르고, 없으면 그 자리에서 새로 만든다. 역할, 확인 여부, 출처 URL. 끌어서 순서 변경.

**사진 업로드**

1. 브라우저가 사진을 WebP 두 크기(1600px, 800px)로 변환한다.
2. 서버에 업로드 URL을 요청한다. 서버는 관리자인지 확인하고 R2 서명된 URL(5분)과 `object_key`를 준다.
3. 브라우저가 R2에 직접 올린다.
4. 성공하면 서버에 사진 정보(object_key, 크기, alt, credit, license, source_url)를 등록한다.
5. 등록되지 않은 채 24시간 지난 파일은 정리 작업이 지운다.

**AI로 초안 채우기**

1. 공간 이름(필요하면 지역)을 넣고 버튼을 누른다.
2. 서버가 AI 초안 서비스를 부른다. 웹 조사 후 주소·좌표·종류·접근 방식·크레딧 후보·출처 후보를 돌려준다. 항목마다 근거 URL이 붙는다.
3. 폼에 **"AI 제안"** 표시와 함께 채워진다. 관리자가 항목별로 받아들이거나 지운다. 받아들이기 전에는 저장되지 않는다.
4. 감상, 감각, 한 줄 소개, 에세이는 채우지 않는다.
5. 호출 한 번마다 `llm_calls`에 기록한다. 실패하면 "초안을 만들지 못했어요"와 함께 폼은 그대로 둔다.

### 만든 사람 `/admin/makers`

- 목록(이름 검색), 수정 폼(slug, 이름, 종류, 소개, 링크, 소속). slug는 공개 공간에 연결된 뒤 잠긴다.

### 오늘의 공간 편성 `/admin/picks`

- 이번 주와 다음 주의 월~금 칸. 칸마다 공개된 공간을 검색해 넣고 한 줄 소개(40자)를 쓴다.
- 이미 편성된 공간은 고를 수 없다. 지난 날짜와 공개 시각(08:00)이 지난 오늘 칸은 수정할 수 없다.
- 편성을 바꾸면 그 날 8시 전까지는 피드에 반영되지 않는다(공개 여부는 시각으로 계산).

### 제보 검토 `/admin/suggestions`

- 공간 제보: **작성 시작**(draft로 바꾸고 등록 폼 열기) 또는 **반려**.
- 크레딧 제보: **반영**(해당 공간 크레딧에 추가) 또는 **반려**.

### AI 호출 기록 `/admin/llm`

- 기간별 호출 수, 입력·출력 토큰, 비용, 평균 지연, 실패율. 최근 호출 목록(대상 공간, 모델, 비용, 지연, 재시도).

### 페이지 재생성 규칙

| 일어난 일 | 다시 만드는 페이지 |
| --- | --- |
| 공간 공개·수정·상태 변경 | 그 공간, 크레딧에 있는 만든 사람들, 둘러보기 |
| 만든 사람 수정 | 그 프로필, 그 사람이 크레딧에 있는 공간들 |
| 매일 08:00 (KST) | 홈 |
| 편성 변경 | 다음 08:00에 홈과 함께 반영 |

## 7. 콘텐츠·운영 규칙

공간 하나를 등록하는 데 30분 이내가 목표다.

### 등록 기준 (모두 충족해야 공개)

- [ ] 다녀온 뒤에도 오래 생각나는 곳인가 (또는 그럴 거라고 확신하는가)
- [ ] 일반인이 방문할 수 있는가 (개인 주택·사무실 제외. 예약·입장권·숙박은 가능)
- [ ] 만든 사람을 출처와 함께 1명 이상 밝힐 수 있는가
- [ ] 공식 인스타그램 공개 게시물(임베드) 또는 출처를 표기할 수 있는 사진이 있는가
- [ ] 최근 3개월 안에 운영 중인 흔적이 있는가

### 등록 흐름

1. 공간 이름으로 **AI로 초안 채우기**
2. 근거 URL을 열어 크레딧과 주소를 확인하고 받아들이기
3. 감상, 감각, 한 줄 소개는 **직접 쓰기**
4. 사진: 공식 인스타그램 공개 게시물이 있으면 임베드를 우선한다. 사진을 올리면 직접 찍은 것(`own`)이거나 출처 이름과 링크를 함께 적는다(`press` · `credited`)
5. 공개
6. 편성 칸에 넣기

### 운영 리듬

| 언제 | 무엇 |
| --- | --- |
| 주말 | 다음 주 5곳 등록·편성 |
| 월~금 08:00 | 자동 공개, 인스타그램에 같은 공간 하나 게시 |
| 금요일 18:00 | 그 주 5곳 뉴스레터 발송 |
| 주 1회 | 제보 검토 |
| 월 1회 | 전체 공간 운영 상태 점검 (휴업·폐업 반영) |

### 사진

- 사용 허락을 따로 받는 절차는 두지 않는다. 대신 모든 사진 아래 "사진: ○○"과 출처 링크를 표기한다(`credit`, `source_url`).
- 공식 인스타그램 공개 게시물이 있으면 사진 대신 임베드를 우선한다.
- 삭제 요청은 48시간 안에 내린다. 요청 창구는 `/about`의 이메일.

### 크레딧 제보 반영 기준

| 제보 | 기준 | 결과 |
| --- | --- | --- |
| 출처 있음 | 출처에서 확인됨 | verified로 반영 |
| 본인이라고 밝힘 | 공식 계정·웹사이트에서 작업 확인됨 | verified, 출처는 그 페이지 |
| 확인 불가 | — | 확인 중으로 반영하거나 반려 |

| AI에게 맡김 | 사람이 함 |
| --- | --- |

## 8. 외부 연동과 비기능 요구사항

### 외부 서비스

| 용도 | 서비스 | 메모 |
| --- | --- | --- |
| 프론트 호스팅 | Vercel Hobby | 비상업만 허용. 수익화하면 Pro |
| 백엔드·DB | 서버 한 대 + Docker Compose | 호스팅 보류 (DECISIONS 9절) |
| 사진 | Cloudflare R2 | 10GB까지 무료, 내보내기 트래픽 무료 |
| 로그인 | 구글 | 카카오는 공개 후(개인 개발자 비즈 앱 전환이 필요) |
| AI | LLM API | 제공자는 구현 시작 때 결정 |
| 뉴스레터 | 메일리 (무료) | 무료는 월 1,000통 또는 4회 발행까지. 주 1회 발송이면 구독자 약 250명까지 무료. 서비스는 구독 폼 링크만 둔다 |

### 뉴스레터 비용 기준

- 구독자 250명 이하: 메일리 무료로 주 1회 발송.
- 250명을 넘으면 둘 중 하나를 고른다: 유료 요금제(월 6,900원부터) 또는 격주 발송으로 바꾸기.
- 직접 발송(Resend 등)은 쓰지 않는다. 무료 플랜이 하루 100통으로 제한되고, 수신 거부·발송 실패 처리를 직접 만들어야 한다.

### 로그인

- 구글 scope: `openid`, `email`, `profile`. OAuth 앱은 "프로덕션"으로 게시한다(테스트 모드는 동의가 7일마다 만료).
- 제공자가 늘어도 계정은 `(provider, provider_id)`로 구분한다. 같은 이메일이라도 제공자가 다르면 별도 계정(MVP 단순화).
- 프론트와 API는 같은 출처(Next rewrites 프록시, DECISIONS 6절)이고, 세션 쿠키는 HttpOnly · Secure · SameSite=Lax.

### 서비스 이름과 검색 노출

- 정식 이름 **"공간의 지은이"**, 줄여 부를 때 **"지은이"**. "지은이"만으로는 모든 책 정보에 나오는 단어라 이름 검색에 묻히므로, 검색에 걸리는 곳에는 정식 이름을 쓴다.
- **페이지 제목 규칙**: `<공간 이름> — 공간의 지은이`, `<만든 사람 이름>의 공간들 — 공간의 지은이`, 홈은 `공간의 지은이 — 오늘의 공간`.
- 계정·도메인도 같은 조합으로 맞춘다(예: jieuni.space, @space.jieuni). 실제 등록 가능 여부는 확인 전.
- 유입의 대부분은 이름이 아니라 **공간·만든 사람 이름 검색**에서 온다. 그래서 이 두 페이지의 제목, 설명, 본문 텍스트가 검색 노출의 핵심이다.
- 구글 서치 콘솔과 **네이버 서치어드바이저**에 모두 등록하고 sitemap을 제출한다.

### 검색 노출과 공유 카드

- 공간·만든 사람 페이지는 정적 HTML로 제목·설명·대표 이미지를 갖는다. `sitemap.xml` 생성.
- 공유 카드(1200×630)는 공간과 만든 사람마다 자동 생성. 카카오톡 공유 미리보기를 배포 전에 확인한다.

### 성능·접근성

- 모바일에서 공간 상세 첫 사진이 2.5초 안에 보여야 한다. 사진은 미리 변환한 WebP, 임베드는 누를 때만 불러온다.
- 모든 사진에 `alt` 필수(공개 시 검사). 누르는 요소는 44px 이상.

### 개인정보

- 이메일·닉네임을 받으므로 개인정보 처리방침을 공개한다(개인정보 보호법 제30조). 처리 목적·항목·보관 기간, 파기, 안전 조치, 열람 청구 방법을 담는다.
- 만 14세 미만은 받지 않는다.
- 분석 도구는 쿠키 없이 개인을 식별하지 않는 것을 쓴다.

### 분석 이벤트

`feed_view`(position), `feed_end`, `card_open`, `save`(status), `follow`, `suggestion_submit`(kind), `newsletter_subscribe`, `share_click`.

## 9. 시드 데이터

`seed/seed.json`은 **개발용 가짜 데이터**다. `dev` 프로필로 뜬 서버가 시작할 때 `makers` 테이블이 비어 있으면 이 파일을 한 트랜잭션으로 적재하고, 행이 있으면 건너뛴다(재기동해도 중복되지 않는다). 운영 프로필에는 이 적재 코드 자체가 없다. 실제 조사 없이 만든 **5곳**으로 화면이 다뤄야 할 모양을 덮는다: 공간 3곳 이상에 크레딧이 있는 만든 사람 1명, 크레딧이 여러 개인 공간, 감각 일부를 비운 공간, 폐업 공간 1곳, 이번 주와 지난주 편성. 아래 예시는 **형식 설명용**이고 실제 시드 값은 가짜다(PLAN B2). 실제 공간 20곳 조사는 AI 평가셋을 만드는 PLAN A1에서 하고, 첫 10곳 등록은 D5에서 관리자 화면으로 한다. 채우다 막히는 필드가 데이터 모델의 빈틈이다.

| 열 | 용도 |

| 막힌 점 | 채우기 어려웠던 필드와 이유. SPEC v0.3의 입력 |

구성(첫 10곳 기준): 머물러 본 곳 3~4곳 + 영상·기사로 만난 곳 6~7곳. 한 만든 사람에 공간이 2곳 이상인 경우를 꼭 넣는다(프로필 격자와 "같은 만든 사람의 다른 공간" 확인용). 후보: 메덩골정원, 체사레, 글로우서울의 공간, LG아트센터.
